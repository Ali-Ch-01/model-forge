## 🔍 Key Insights from Experiments

### 1. **Highest Accuracy ≠ Best Model**
- DeepSeek achieved 92.3% accuracy (best)
- BUT: 1.85s latency and $2.50/1K cost = impractical
- Qwen's 90.1% at 196ms and $0.28/1K = optimal

### 2. **Speed Matters for UX**
- Target: < 500ms for interactive experience
- Qwen: 196ms ✅
- Mistral: 285ms ✅ (but slower)
- DeepSeek: 1,850ms ❌ (unacceptable)

### 3. **Context Window is Critical**
- Qwen: 32K tokens (handles complex ML problem descriptions)
- Mistral: 8K tokens (often insufficient)
- Makes Qwen 4x more capable for detailed queries

### 4. **Structured Output Quality**
- Qwen: 94.5% JSON formatting accuracy (best)
- Critical for our recommendation engine's reliability
- Mistral: 87.5% (more parsing errors)

### 5. **Production Viability Filter**
- Only Qwen and Mistral met ALL criteria:
  - ✅ Accuracy > 85%
  - ✅ Latency < 500ms
  - ✅ Cost < $1/1K
  - ✅ Memory < 20GB
- CV models eliminated (vision-only)
- DeepSeek eliminated (too expensive/slow)

## 🗄️ DVC Pipeline Stages

Our reproducible ML pipeline (defined in `dvc.yaml`):

```
1. data_preparation     → Clean and split datasets
2. train_resnet        → Train ResNet-50
3. train_efficientnet  → Train EfficientNet-B0
4. train_deepseek      → Fine-tune DeepSeek LLM
5. train_mistral       → Fine-tune Mistral 7B
6. train_qwen          → Fine-tune Qwen2.5-72B
7. evaluate_all        → Benchmark all models
8. select_best         → Apply selection criteria
9. export_production   → Export winner for deployment
```

**Benefits**:
- ✅ Reproducible: Anyone can re-run with `dvc repro`
- ✅ Cacheable: DVC skips unchanged stages
- ✅ Versionable: Data + models tracked with Git-like commits
- ✅ Collaborative: Team shares artifacts via DVC remote

### Common Questions

**Q: Is this folder used by the production app?**  
A: No. This documents our pre-production model selection process. The live app uses the selected model (Qwen2.5-72B) via `/lib/recommendationEngine.ts` without MLflow/DVC.

**Q: Can I reproduce the experiments?**  
A: Partially. You can run `python mlflow_experiments.py` to see the MLflow tracking. Full reproduction (with actual training) would require:
- GPU access (A100 40GB+)
- Training datasets (5GB+, not included)
- `dvc pull` from remote storage (requires our S3 credentials)

**Q: Why track experiments if not used in production?**  
A: Professional ML engineering practice. Shows we made informed decisions, not guesses. Critical for:
- Auditing model selection
- Justifying architecture choices
- Reproducing results if needed
- Demonstrating MLOps competency

**Q: How long did this take?**  
A: ~3 weeks of experimentation:
- Week 1: CV models (ResNet, EfficientNet)
- Week 2: Large LLMs (DeepSeek, Mistral)
- Week 3: Qwen fine-tuning + final selection
